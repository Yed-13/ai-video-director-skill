# 阶段 7：收片、检查、修复

用户把生成好的视频放进 `shots/sNN/takes/sNN_takeK.mp4` 之后，按下面的步骤处理。

## 检查

```bash
python3 scripts/clip.py inspect shots/s03/takes/s03_take1.mp4 \
  --first shots/s03/first.png --last shots/s03/last.png
```

输出在 `shots/s03/review/s03_take1/`：

- `info.txt`：时长、分辨率、帧率、有没有音轨、色彩空间
- `contact.jpg`：均匀抽 12 帧拼成的联系表，先看这张
- `first_frame.png` / `last_frame.png`，以及它们和 `first.png` / `last.png` 的 SSIM 相似度（越接近 1 越像）
- `drift.csv` 和 `drift.txt`：逐帧的平均亮度和饱和度，用来发现"越来越暗、越来越冷"这种漂移
- `frames/`：每 0.5 秒一张全分辨率帧，可疑的地方放大看

对照分镜逐项看：

1. 动作对不对、先后顺序对不对、往哪边走
2. 人数、道具数量有没有变；有没有凭空出现的东西
3. 脸、手、身形有没有变形
4. 开头和结尾几帧有没有突变（突然变锐、突然跳到尾帧的样子）
5. 颜色和亮度有没有漂移
6. 嘴是不是自己在动

写进 `review/s03_take1/report.md`，每条写：时间、帧号、问题、处理建议。最后写清楚**哪些你没法确认**：动作是否流畅、节奏手感、声音。

## 处理顺序：剪 → 修 → 重拍

发现问题不要马上重拍：

1. **能剪掉吗**？问题只出现在开头或结尾几帧，直接剪掉。
2. **能用代码修吗**？
   - 结尾几帧突然跳变：选一张没问题的帧，后面都停在这一帧
   - 第一帧特别锐：去掉第一帧
   - 越来越暗、越来越冷：按首帧的亮度和饱和度逐帧校正回来（只调亮度和饱和度，不动色相）
   - 和同一场戏的其他镜头颜色不一致：`python3 scripts/look.py compare <这场戏的基准帧> <这条 take>`，按给出的校正参数调，再量一次
   - 推镜不够：在后期用缩放再推一点
   - 节奏不对：变速、或者剪掉中间几帧
3. **能补吗**？问题出在中间一小段（手指变形、杯子变大、脸突然变了）时：
   - 用 `clip.py stills --at <秒>` 截出出问题之前的最后一张好帧；
   - 用生图模型（Codex）把这张图里要保持的东西修好，作为新首帧；需要的话再画一张尾帧；
   - 只重新生成这一小段（首帧生视频或首尾帧生视频），剪回原来的位置。
4. **只能重拍时**：先改提示词或首尾帧（或白膜），找到出问题的原因再拍。原样再拍一次，大概率还是错的；只想换一种结果就换 seed。只重拍这一段。

旧的 take 一律保留。最后所有能用的 take 放在一起挑。

## 已知的模型习惯

- **Seedance 2.5 / 较新版本**：写了"没有音乐"有时还会混入音乐；结尾几帧可能突然跳到尾帧的样子；第一帧可能特别锐。
- **Seedance 2.0 mini**：越到后面画面越暗、越冷；自带的音效经常可以直接用。
- **MiniMax H3（本地 768p）**：没有经过官方 Context-IR 预处理，质量很依赖提示词写得是否接近官方格式；小字和精细细节在 768p 下容易糊（2K 重生成模块没有开源）。
- **所有模型通用的常见错误**（检查清单）：每段角色长得不一样（喂身份板）；场景一会儿一个样（一段只喂一张场景图）；人物瞬移、左右颠倒（先写站位，对照机位图）；角色张着嘴念心里话（内心独白要单独写）；同一个角色声音变了（声音描述写死，或用音频参考）；道具忽大忽小（写实际尺寸）；同一个人出现两次；场景前后矛盾（夜景窗外是白天）。

每做完一支片子，把新发现的习惯补进这一节。
